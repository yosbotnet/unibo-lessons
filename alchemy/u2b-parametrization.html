Parametrization: why the learning rate moves with size, µP, and Muon

~70 min read3 widgets (2 compute live in your browser)6 sealed predictions3 audit drillslab: A2 problem 4.1 on Modal

The unit in one paragraph

Unit 1 showed that the best learning rate moves when the model grows, so a ladder of sizes trained at one rate measures mis-tuning as much as size. This unit asks why it moves, and whether it has to. The answer is a piece of arithmetic: with Adam, every weight moves by about the learning rate, and a matrix with fan-in n sums n of those moves; when the moves line up with the input, the output changes n times as much. Undo that factor, layer by layer, and you get µP, a way of writing the model so the best learning rate stays put as width grows. You will run a real coordinate check in the browser, predict four results CS 312 measured on its own model (and see how far the theory carries), extend the idea to depth, and meet Muon, an optimizer that takes the same arithmetic one step further by controlling the size of every update direction at once. Three fictional audit drills close the unit: each is a confident conclusion built on a parametrization that was not what the log said it was.

1. Why the learning rate moves with width

Start with a prediction, before any argument. Lock it, then read on.

A ReLU network in the standard parametrization (Kaiming initialization, one learning rate for every matrix) takes one Adam step at a fixed learning rate. Look at the second hidden layer, an n×n matrix. As width n goes from 64 to 2048, how does the RMS change of that layer’s output features grow?

  1. It shrinks, roughly like 1/√n: more weights share the work
  2. It stays about the same: Kaiming initialization already normalizes for width
  3. It grows roughly like √n
  4. It grows roughly like n

Roughly like n. The argument is below. The widget in section 4 runs this exact experiment on a toy network: the fitted log-log slope over widths 64–2048 is 0.88, and the last doubling (1024 → 2048) multiplies the change by 1.87. The slope is a little under 1 because a second, width-independent term (the change of the layer’s input) still matters at small widths.

derived from the alignment argument · measured in the toy MLP of section 4, computed by this page

Why n? Think about what Adam does on its first step. With bias correction, step one has m̂ = g and v̂ = g², so the update is g/|g|: every weight moves by exactly ±η. Later steps are not exactly signs, but stay of order η per entry. So under Adam the size of each weight change does not depend on width. What depends on width is how those changes add up.

Take one row of a hidden matrix and one example. The gradient of a linear layer is an outer product, δ x⊤: row i is δi times the input x. Its sign pattern is therefore sign(δi)·sign(xj), and the change that row makes to its output on that same input is

Δzi = Σj ΔWij xj = −η sign(δi) Σj |xj| ≈ −η · n · mean|x|   n terms, all with the same sign

Every one of the n terms pushes the same way, because the update was built from the input it is now applied to. If the signs were random instead, the sum would grow like √n, the way a random walk does. These are the two reference cases CS 312 calls full alignment (n) and no alignment (√n). Batching many examples into one gradient blurs the outer product a little, but on the inputs the network actually trains on, the update stays strongly aligned.

So in the standard parametrization a hidden matrix’s effect on its output grows like η·n. To keep that effect the same size as you widen, η has to shrink like 1/n. CS 312 measured exactly this on its own model: in the course baseline, the best learning rate falls roughly as 1/n with width measured. This is the mechanism behind unit 1’s warning about ladders at one learning rate (unit 1): the larger rungs are not just bigger, they are hotter.

Your move: the input layer of a language model maps a fixed vocabulary (or a fixed 32-dimensional input) to width n. Does its learning rate need to shrink with n?

No. Each output coordinate of the input layer sums over the fan-in, which is the vocabulary or input dimension, and that does not grow with width. With Adam each weight still moves by about η, and each output sums a fixed number of those moves, so the change per coordinate is independent of n. Only matrices whose fan-in grows with width need the 1/n correction. Section 4’s widget shows it: layer 1 (fan-in 32) moves the same amount at every width under both parametrizations.

2. What we want from a wide network

“Shrink the LR like 1/n” is a patch. To decide what the right patch is for every layer, lecture 4 states what a good infinite-width limit should look like. Take width to infinity at a fixed training step, with order-one inputs. Then we want:

  • Stable: hidden features have constant size at initialization (Θ(1) RMS), they change by at most a constant amount during training, and the logits stay bounded (O(1)).
  • Nontrivial: the logits change by a constant amount at some step. This rules out the useless stable limits, such as a zero learning rate.
  • Feature learning: hidden features themselves change by a constant amount, not a vanishing one. If the change shrinks like n−r, then r < 0 is unstable, r = 0 learns features, r > 0 means the features freeze as the network grows.
Aside: the stable limit we do not want

There is a famous limit that is stable and nontrivial but fails the third condition: the neural tangent kernel (Jacot et al., 2018). Scale the output by 1/√n, keep weights and learning rate of order one, and each weight moves only O(n−1/2). The network stays a linear function of its parameters around initialization: training becomes kernel regression on fixed features, and the first layer barely moves. It is mathematically tidy and empirically much worse than real networks. Stability alone is not the goal; the point of µP is to find the limit where every layer keeps learning.

One warning that lecture 4 makes explicitly: all of this is leading-order arithmetic, “physics math”. It assumes the terms being added are independent enough not to cancel. Two quantities of size n can subtract to something of size log n. The rules below are a strong starting point, and section 5 shows how far they hold up on a real model.

3. The abc parametrization and the µP table

Following Everett et al. (2024), write each layer with fan-in n using three exponents: a forward multiplier n−a, an initialization scale with variance σ²n−2b, and a learning rate ηn−c. The hyperparameters σ and η are the ones we hope to tune once.

z = n−a W x,   Wij ~ N(0, σ² n−2b),   LRW = η n−c

Three facts fix the exponents, for Adam with full alignment:

  1. Initialization. A random matrix applied to an independent input sums n random terms, so the output scale is n1/2−a−b. Hidden features of constant size need a + b = 1/2. Kaiming initialization is the choice a = 0, b = 1/2 (with σ² = 2 for ReLU).
  2. The direct update. Adam moves each entry by about ηn−c and, fully aligned, a row sums n of them, so the update’s effect is ηn1−a−c. Feature learning needs a + c = 1.
  3. The readout. Its output dimension (the vocabulary) does not grow, and as training proceeds the readout’s weights become aligned with the features feeding it. Its response to a feature change is then n1−a−b, which must be order one: a + b = 1. A consequence: initial logits shrink like n−1/2, which is allowed (logits need only be bounded).

Inputs with a fixed fan-in need a + b = a + c = 0. Choosing a = 0 where possible and writing m = n/n0 for the width multiplier over a reference width n0 (where everything matches the tuned baseline), assignment 2 summarizes one valid choice:

inputhiddenreadout
(a, b, c)(0, 0, 0)(0, ½, 1)(1, 0, 0)

Read the bold cells as the three changes from the standard parametrization: hidden matrices get a learning rate that falls with width, and the readout gets a fixed initialization scale plus a 1/m multiplier in the forward pass. Everything else is Kaiming. At m = 1 nothing changes, which is the point: you tune at n0, then widen.

Your move: suppose updates were not aligned with their inputs (the √n case). What would the hidden learning rate be?

The direct update would be ηn1/2−a−c, so with a = 0 we need c = 1/2: a hidden LR of η/√m. That is assignment 2’s problem 4.0, and it is the reason the alignment exponent matters. Lecture 4 shows measured alignment during training between about 0.5 and 1.0, so the truth sits between the two prescriptions. Keep that in mind for section 5.

4. Coordinate check, in your browser

A coordinate check is the standard test of a parametrization (Yang et al., Tensor Programs V): train a few steps at several widths with the same base learning rate, and plot how much the features move against width. If the parametrization is right, the lines are flat. It costs seconds, and it catches most implementation mistakes before any real run.

Three things to notice. At width 64 the two lines start at the same point: m = 1, so the two parametrizations are the same network. Under SP the slope for layer 2 is a little under 1 at small widths because the layer’s output also changes through its input (layer 1 moved), a width-independent term; once the n-proportional term dominates, each doubling roughly doubles the change. And the logits under SP grow faster than n because two effects stack: the readout’s own update, and the readout amplifying the already inflated layer-2 change.

For directing an agent

A coordinate check is the cheapest evidence you can ask for that a parametrization was implemented as described. If a log says “we switched to µP” and there is no flat coordinate-check plot, you do not yet know that the code does what the log says. Ask for the plot before any transfer claim.

What these two numbers teach is not “µP works” or “µP fails”, but how to reason when only part of a recipe is applied: find which matrices carry the width dependence, and ask which of them the change actually touched. The same question returns in drill 1.

Transfer is not the same as the best loss

Assignment 2 asks this repeatedly: does the prescription with better learning-rate transfer also reach a lower loss after tuning? Not necessarily. Transfer saves you the sweep at the large width; it does not promise that the transferred model beats a separately tuned standard-parametrization model. A director should keep these as two claims and ask for evidence of each.

6. Depth: residual multipliers and Adam’s ε

Width is not the only axis. A transformer adds every block’s output into a residual stream, xl+1 = xl + cL·fl(xl), and with L blocks the same counting game applies. Independent random blocks at initialization add like a random walk, so the residual stream grows like √L. Updates during training are more coherent (all blocks are pushed by the same loss), so their effects add more like L. Assignment 2 compares three prescriptions, with reference depth 2 and r = L/2, applied on top of µP for width:

Depth-µP (Yang et al., Tensor Programs VI; Bordelon et al., 2023) uses 1/√L, matched to the random-walk sum: the residual stream stays order one at initialization. CompleteP (Dey et al., 2025) uses 1/L, matched to the coherent sum, and keeps each block’s own learning rate at η so that every block still learns features of its own (the paper’s title is “Don’t be lazy”: under depth-µP’s shrinking block LR, deep blocks drift toward lazy, linearized behaviour). In assignment 2’s five-step stress test with independent blocks, the course’s own playtest found depth-µP did best and CompleteP over-corrected measured. Quiz 2 then changed one thing.

Depth L = 1000 (r = 500), width 64. The 1,000 blocks are now one shared block, initialized like one block of the stress test and applied 1,000 times. Let ρ = (RMS of the final residual stream at initialization, shared block) / (the same with 1,000 independent blocks), same prescription and seed. For which prescriptions is ρ below 10?

  1. None of them
  2. Standard µP only
  3. Depth-µP and CompleteP
  4. CompleteP only
  5. All three

CompleteP only: measured ρ ≈ 32.2 (standard µP), 28.6 (depth-µP), 1.56 (CompleteP). A shared block adds the same contribution 1,000 times, coherently, instead of 1,000 independent ones that partly cancel, so the branch sum grows by a similar factor in every prescription, of the order of √1000 ≈ 32: the course’s table shows 33 → 1,062 (32×), 0.89 → 38.4 (43×), and 0.036 → 1.20 (33×). The multiplier scales the shared and the independent sums alike, so it largely cancels from the branch-sum ratio.

Then why is CompleteP’s ρ only 1.56? Because the residual stream is not only the branch sum: it also carries the embedding, with RMS about 1. Under CompleteP the branches add only 0.036 with independent blocks, so the stream’s RMS is essentially the embedding’s (1.00), and sharing raises it to 1.56. The trap is reading an RMS ratio as if it measured only the part you were thinking about.

CompleteP. A shared block is the limiting case of coherent updates: every application receives the same update, so the 1,000 contributions are perfectly aligned. CompleteP’s 1/L multiplier is designed for exactly that, while depth-µP’s 1/√L is designed for incoherent sums. The course’s rationale is one line: CompleteP targets full alignment, and block copying is full alignment. The lesson for prediction: which prescription wins depends on which alignment regime the experiment is in, and changing the experiment can flip the winner.

The ε gotcha

Why does the table scale Adam’s ε? Adam’s update is m̂/(√v̂ + ε). Everything above assumes that ratio is about ±1, which holds only while gradient entries are much larger than ε. But the prescriptions shrink gradients: a residual multiplier cL multiplies every gradient flowing into a block, and the readout’s 1/m multiplier scales the signal flowing back into the whole network. Once gradient entries approach 10−8, ε takes over, the update shrinks below η, and the model is silently running a different parametrization from the one the log names. Scaling ε with the multiplier, as assignment 2 does, keeps the ratio intact. Everett et al. (2024) report that ε matters at scale for exactly this reason and propose Adam-atan2, which removes it.

Your move: a run log reports “median |gradient| of hidden matrices: 3×10−9” and the optimizer config says eps = 1e-8. What is the effective step, roughly, compared with what the parametrization intends?

Where √v̂ ≈ 3×10−9, the update is about 3×10−9/(3×10−9 + 10−8) ≈ 0.23 of the intended ±1, so those matrices move at roughly a quarter of their nominal learning rate, and coordinates with smaller gradients even less. The learning rate in the config is no longer the learning rate the model sees. Either scale ε down, or treat any width or depth comparison from that run as confounded.

7. Muon: the update as a polar factor

µP chooses initialization and learning rates so that an Adam update moves features by the right amount. Lecture 4 then asks the question the other way round: what if the update itself were built to move features by the right amount, in every direction at once?

Gradient descent picks the step that most decreases a linear model of the loss inside a small ball: minimize ⟨G, ΔW⟩ subject to ΔW being small. With the usual Euclidean ball you get −ηG. But the quantity µP cares about is how much ΔW can change the output, ‖ΔW x‖ ≤ ‖ΔW‖op‖x‖, which is controlled by the operator (spectral) norm, the largest singular value. Use that ball instead, and the answer is clean (Bernstein and Newhouse, 2024): if G = UΣV⊤, then

argmin‖ΔW‖op ≤ ρ ⟨G, ΔW⟩ = −ρ U V⊤   keep the singular directions, set every singular value to 1

UV⊤ is the polar factor of G. Every direction the gradient points along gets the same step size, however small its singular value was. That is “idealized Muon”. Practical Muon (Keller Jordan, 2024) makes three changes: it orthogonalizes the momentum (Nesterov style) rather than the raw gradient; it replaces the SVD with five steps of a Newton–Schulz iteration, which uses only matrix multiplies; and it applies only to the 2D hidden matrices, leaving embeddings, the output head, and every scalar or vector parameter to AdamW.

Newton–Schulz, and why it does not reach 1

Divide the matrix by its Frobenius norm, so all singular values are at most 1. Then repeat, with A = XX⊤:

X ← aX + (bA + cA²)X,   (a, b, c) = (3.4445, −4.7750, 2.0315),  5 times

Each step keeps U and V and applies the scalar polynomial p(σ) = aσ + bσ³ + cσ⁵ to every singular value. The coefficients are tuned for speed: a slope of 3.4445 at zero means small singular values grow fast. The price is that 1 is not a stable fixed point, so the values do not converge; they settle into a band.

A 64×128 matrix is divided by its Frobenius norm; its singular values then range from 0.013 to 0.85 (a ratio of 67). After Muon’s five Newton–Schulz steps, what do its singular values look like?

  1. All equal to 1 to three decimals: that is what orthogonalization means
  2. All within 1% of 1
  3. Spread over a band, roughly 0.7 to 1.2
  4. Still spread by a ratio near 67: five steps are too few to change the shape much

A band. Computed by the widget below: after five steps every singular value lies between 0.683 and 1.134 (ratio 1.66, down from 67). Applying p five times to any starting value between 0.002 and 1 lands in [0.68, 1.20]; iterate forever and the values keep cycling within [0.68, 1.13] instead of converging. Values below about 0.001 do not make it in five steps (0.001 only reaches 0.47). Jordan’s post says the coefficients were chosen to land within roughly 1 ± 0.3, and that this tolerance did not hurt the loss curve in his runs.

Look at the gradient-like matrix at k = 0: four large singular values (the signal) and sixty small ones (noise). Muon raises the small directions to the same step size as the large ones. That is the bet Muon makes: that rare directions in the update are under-served by gradient descent and Adam. Whether that is exactly the right bet is still open; lecture 4 closes with evidence that the precise spectrum is not what matters, and that perfectly uniform singular values are not optimal either. Treat “Muon works because it orthogonalizes” as a hypothesis with good results behind it, not a settled mechanism.

The patches that make it work at scale

  • Momentum, Nesterov style, orthogonalized after accumulation (Jordan).
  • AdamW for everything else: the embedding (its input is a one-hot lookup, not a dense feature vector), the output head, and gains and biases (Jordan’s post: AdamW on the embedding and final head gives the best results).
  • Update RMS matching (Liu et al., Moonlight; used again in Kimi K2): scale the orthogonalized update by 0.2·√max(A, B) for an A×B matrix. Why that factor: UV⊤ has min(A,B) singular values equal to 1, so its RMS entry is 1/√max(A,B) derived; the factor brings the RMS to 0.2, comparable to a typical AdamW update, so AdamW’s learning rate and weight decay become usable starting points. Without it, a Muon step at AdamW’s learning rate is a much smaller step.
  • Weight decay added to the Muon update (Moonlight; Kimi K2 trains with decay 0.1).
  • QK-Clip (Kimi K2’s MuonClip): after each update, for any attention head whose largest pre-softmax logit in the batch exceeded a cap (τ = 100 in K2), scale that head’s query and key weights down so the logit returns to the cap.

8. Audit drills

Each drill is a fictional research log written by an agent, ending in a confident conclusion. Tick every problem that undermines the conclusion, and leave unticked anything that is true in general but not a problem here. The logs are invented for this course; the mistakes are the ones this unit is about.

Which of these undermine the conclusion in W-17?

  • The readout is only half converted: the 1/m multiplier was added but the initialization stayed at 1/√n instead of the fixed 1/n0.
    The model is neither SP nor µP; it is a third parametrization, and its transfer properties are unknown. W-15 says no coordinate check was run, which is the test that would have caught it. A failure to transfer here says nothing about µP.
  • Adam’s ε = 10−8 is larger than the typical hidden-matrix gradient at width 2048 (4×10−9).
    At that ratio Adam’s update is roughly 4/(4 + 10), under a third of the intended size, for most hidden coordinates. The effective hidden learning rate at width 2048 is not η/m, so “the transferred LR” was never actually applied. µP setups scale or remove ε for this reason (section 6).
  • The reference sweep and the transfer run used different data mixes (v3 against v4).
    The best learning rate can depend on the data. A transfer test holds everything fixed except width; this one changed two things, so even a perfect µP could have shown a shifted optimum. The SP comparison at 2048 used v4, which makes the 2.31 vs 2.19 comparison fair, but not the transfer claim.
  • A reference width of 128 is too small; µP needs the reference model to be at least 1024 wide.
    No such requirement. The reference width is just where the parametrization matches the baseline you tuned; µP’s point is that it can be small. Assignment 2 transfers from 512 down to 128 and up to 1024, and the coordinate check in section 4 uses 64.
  • The embedding learning rate should also have been divided by m.
    For Adam, the input layer keeps learning rate η: its fan-in (the vocabulary) does not grow with width, so each output coordinate sums a fixed number of moves (section 1). Dividing it would freeze the embedding at large width.
  • µP is derived for SGD; with Adam it cannot be expected to transfer.
    The table in section 3 is the Adam version; Adam’s sign-like updates are what make the arithmetic simple. SGD has its own, different table.

Debrief. The log names a method (“µP”) and then runs something else: a half-converted readout, and an ε that quietly rescales the hidden learning rate at the large width. Add a data change between the two ends of the transfer, and no conclusion about µP is available. What to ask for: a coordinate check at 128 and 2048 (flat lines, seconds of compute), ε scaled or checked against gradient magnitudes, and a small learning-rate sweep at the target width on the same data, which is the only thing that shows where the optimum actually is.

Which of these undermine the conclusion in B-34?

  • Muon was applied to the token embedding and the output head.
    Standard Muon leaves the embedding, the head, and all vector parameters on AdamW. Orthogonalizing an embedding update makes little sense (its input is a one-hot lookup), and Jordan reports AdamW on the first and last layers works best. This is a nonstandard Muon.
  • Muon ran at AdamW’s tuned learning rate, with no update RMS matching and no weight decay.
    An orthogonalized update for a 1024×4096 matrix has RMS 1/√4096 ≈ 0.016 per unit learning rate, far below a typical AdamW update; without the 0.2·√max factor, the same number means a much smaller step. A tuned AdamW was compared with an untuned Muon, which is unit 1’s first lesson about comparing arms.
  • Both runs were compared at 30% of the schedule, inside the stable phase, before any decay.
    Unit 1: rankings in the stable phase can change after the decay, and different optimizers can sit at different heights on the “river” while making similar progress along it. Compare after decay, or run a short decay from the 12k checkpoint for both.
  • Only one seed per arm, so the 0.033 gap could be noise.
    Not here: the log reports a measured seed std of 0.004, so a 0.033 gap is about eight standard deviations. The gap is real. The problem is what it is a gap between: a misconfigured Muon and a tuned AdamW, mid-schedule.
  • Five Newton–Schulz steps leave singular values off 1, so the update is not really orthogonal.
    By design: the quintic lands in a band around 1 (section 7) and Jordan reports this tolerance does not hurt. Running more steps would not fix this comparison.
  • Nesterov momentum should be off for Muon.
    Standard Muon uses Nesterov momentum (0.95). Nothing here is unusual.

Debrief. A decisive-looking gap, well outside the noise, can still answer the wrong question. Three configuration choices each push against Muon, and the comparison point is mid-schedule. What to ask for: Muon on hidden matrices only, RMS-matched update with weight decay, a small learning-rate sweep for Muon (it is a different optimizer and gets its own), and a comparison after the decay. A director who checked only “how many seeds?” would have passed this log.

Which of these undermine the conclusion in C-10?

  • The learning rate was tuned only at 12 layers and reused at 24 and 48.
    Without a depth prescription, the best learning rate moves with depth just as it moves with width. The 48-layer rung was trained at a rate tuned for a different model, so the ladder mixes depth with mis-tuning.
  • No residual multiplier: the residual stream grows with depth, so each extra block is a smaller share of what the final norm sees.
    C-09 shows the stream growing by about √2 per doubling (9.8 → 14.1 → 20.3), the random-walk signature. In a pre-norm network each later block adds a fixed-size contribution to an ever larger stream, so deep blocks are muted. The ladder measures this parametrization’s depth scaling, not the task’s. Depth-µP or CompleteP (section 6), with the learning rate checked at each depth, is the comparison that could support C-10.
  • Three seeds are too few to see the gain from 12 to 24 layers.
    The 12 → 24 gain (0.0085) is about eight standard deviations. Seeds are not the issue for that step, and the 24 → 48 difference is small either way; the question is why it is small.
  • The runs should have been compared at the end of the stable phase, not after decaying to zero.
    The opposite: comparing after decay is the right practice (unit 1). Equal tokens with a full decay is the fair part of this design.
  • Pre-norm should be replaced by post-norm for deep models.
    Pre-norm is the standard for deep transformers precisely because post-norm is harder to train at depth. Swapping it would not answer the question C-10 asks.

Debrief. “X stops helping” is a claim about the task, but an unscaled ladder at one learning rate tests the parametrization. The log even contains the evidence (the growing residual RMS) and does not use it. What to ask for: a depth prescription (residual multiplier and its matching LR and ε rules), a short learning-rate sweep at the deepest rung, and only then a statement about depth.

Check your understanding

Why does the best Adam learning rate of a hidden matrix fall like 1/n in the standard parametrization?

Adam moves each weight by about η regardless of width, and a gradient built from an input is aligned with that input, so a row’s n moves add up coherently: the output changes by about η·n. Keeping that change constant needs η ∝ 1/n. With unaligned updates it would be 1/√n.

What three changes turn a Kaiming-initialized network into µP for Adam?

Hidden matrices: learning rate η/m. Readout: initialization variance fixed at 1/n0 and a forward multiplier 1/m. Inputs and everything else: unchanged. At m = 1 the model is the tuned baseline.

What does a coordinate check plot, and what should it look like?

The RMS change of each layer’s features (and of the logits) after a few steps at a fixed base learning rate, against width on log-log axes. Under a correct parametrization the lines are flat; under SP, layers with width-growing fan-in rise with slope near 1.

Why is the NTK limit not what we want, even though it is stable?

Each weight moves only O(n−1/2), so the network stays linear around its initialization and its features never change: kernel regression on fixed features. It performs much worse than real networks. µP is the limit where features keep changing by a constant amount.

Depth-µP uses cL = r−1/2, CompleteP uses r−1. Which assumption is each built on?

Depth-µP: block contributions add incoherently (random walk, √L), as at initialization. CompleteP: they add coherently (L), as aligned updates do, while keeping each block’s LR at η so every block learns. A shared block is the fully coherent case, which is why CompleteP wins quiz 2 Q1.

Why do width and depth prescriptions scale Adam’s ε?

The multipliers shrink gradients. Once gradient entries approach ε, Adam’s update falls below its intended size and the effective learning rate is no longer what the parametrization prescribes. Scaling ε with the multiplier keeps the update sign-like.

What does Muon compute, and what do five Newton–Schulz steps actually return?

The polar factor UV⊤ of the momentum: the steepest-descent step under the operator norm, every singular value set to 1. Five quintic Newton–Schulz steps approximate it with matrix multiplies only; singular values land in a band (0.68–1.13 on this page’s matrices), not exactly at 1, by design.

Name four patches that practical Muon needs.

Nesterov momentum; AdamW for embeddings, the output head and vector parameters; update RMS matching by 0.2·√max(A,B) plus weight decay (Moonlight, Kimi K2); QK-Clip on attention heads whose logits exceed a cap (Kimi K2).
